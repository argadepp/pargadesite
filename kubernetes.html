01 · Understand the topic

What is Kubernetes Fundamentals?

Kubernetes is an orchestration platform that manages containerised applications across a cluster of machines. You describe the desired state and Kubernetes controllers work to keep the actual state aligned.

Why is it useful in DevOps?

Kubernetes helps teams deploy, scale and recover container workloads consistently. Learn core objects and networking before jumping into managed clusters such as EKS or AKS.

02 · Core knowledge

Important concepts to understand

Cluster & node

A cluster is the control plane plus worker nodes. Nodes provide compute capacity.

Pod

The smallest deployable unit; it contains one or more closely related containers.

Deployment

Manages ReplicaSets and keeps the desired number of Pods available.

Service

Provides a stable network endpoint for a changing set of Pods.

ConfigMap & Secret

Provide configuration to workloads; secrets need appropriate encryption and access controls.

Ingress

Defines HTTP routing from outside the cluster to Services, typically through an ingress controller.

Namespace & RBAC

Namespaces organise resources; RBAC controls who can perform actions.

PersistentVolume

Represents storage that outlives an individual Pod.

03 · Command reference

Commands and real-world use cases

Run these in a lab environment first. Some commands require the related tool to be installed and configured.

CommandWhat it doesWhen you use it
kubectl get nodesList cluster nodesCheck whether worker nodes are Ready.
kubectl get pods -AList Pods across namespacesGet a quick workload overview.
kubectl describe pod PODShow Pod details and eventsInvestigate scheduling, probes, mounts and image errors.
kubectl logs PODRead container logsInspect application startup and runtime output.
kubectl exec -it POD -- shRun a command in a containerDebug a running workload when the image includes a shell.
kubectl apply -f app.yamlApply declarative resourcesCreate or update objects from manifests.
kubectl get svc,deploy,ingressList common application resourcesUnderstand workload exposure and desired replicas.
kubectl rollout status deployment/appWait for rollout statusVerify a deployment completes.
kubectl rollout undo deployment/appUndo a deployment rolloutReturn to a previous ReplicaSet when appropriate.
kubectl get events --sort-by=.metadata.creationTimestampSort cluster eventsFind recent scheduling and runtime issues.
04 · Learn in sequence

Step-by-step learning plan

  1. Create a local cluster with kind, minikube or another beginner-friendly tool. Learn kubectl context and namespace.
  2. Deploy a simple container as a Pod, then learn why Deployments are preferred for long-running applications.
  3. Expose Pods with a ClusterIP Service. Understand labels and selectors; observe how the Service finds endpoints.
  4. Add ConfigMaps and Secrets, resource requests/limits, readiness and liveness probes.
  5. Learn namespaces, RBAC, volumes and basic ingress routing. Understand that an ingress resource needs a controller.
  6. Practise troubleshooting: Pending, ImagePullBackOff, CrashLoopBackOff, failed probes, DNS and service connectivity.
05 · Hands-on practice

Mini project / lab

Deploy a web app with a Deployment, Service and Ingress in a local cluster. Scale it to three replicas, change the image, watch rollout status and deliberately introduce then fix a bad image tag.

Tip: Save your notes, commands, screenshots and troubleshooting findings in a GitHub repository. Your learning record becomes part of your portfolio.
