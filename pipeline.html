How a DevOps pipeline works

Follow one code change from a developer's laptop all the way to a running, monitored application. This example uses GitHub, Jenkins, Docker and Kubernetes.

Complete DevOps lifecycle diagram

Read the top row from left to right for Continuous Integration (CI). The flow then continues to the bottom row for delivery and deployment (CD). Monitoring sends feedback to the team so the next change can be improved.

Follow the code

What happens at each stage?

1. Developer writes and commits code

The developer changes application code, runs local checks, then uses git add, git commit and git push to send the change to a remote Git repository.

2. GitHub stores the source

The repository stores the code and its history. A push or pull request can trigger a webhook event. Branch protection can require reviews and successful checks before merging.

3. Jenkins receives the trigger

The Jenkins controller receives the webhook and schedules the pipeline. A Jenkins agent does the actual work, keeping orchestration separate from build execution.

4. Jenkins runs CI checks

The agent checks out the commit, installs dependencies, compiles the application, runs unit tests, linting and optional static security or code-quality scans. A failed required check stops the pipeline.

5. Docker packages the app

After checks pass, Jenkins builds an image from the Dockerfile. Tag it with an immutable identifier such as the Git commit SHA, and scan it for known vulnerabilities.

6. Registry stores the image

Jenkins authenticates using a securely stored credential and pushes the image to Docker Hub, Amazon ECR, Azure Container Registry or another registry.

7. Jenkins CD deploys it

A deployment job updates the target environment using Helm or kubectl. Production deployments may require an approval, environment protection and a controlled rollout strategy.

8. Kubernetes runs the app

Kubernetes pulls the image and runs it in Pods. Deployments manage replicas and rollouts; Services provide stable networking, while Ingress or a load balancer exposes the app.

9. Monitoring closes the loop

Prometheus collects metrics, Grafana visualises them, and a logging platform helps investigate failures. Alerts notify the team when availability or performance degrades.

Try this as a learning project

Build the same flow in a safe test environment

  1. Push a small web application to a GitHub repository.
  2. Install Jenkins locally or use a test Jenkins server, then connect a webhook or poll SCM.
  3. Create a Jenkinsfile with checkout, build, test and Docker build stages.
  4. Push the image to a test registry using Jenkins credentials; never hard-code tokens in the Jenkinsfile.
  5. Deploy to a local Kubernetes cluster such as kind or k3d and verify the rollout.
  6. Add a simple dashboard and an alert. Practise rolling back to the previous image tag.

Important: This is a learning architecture, not a universal production blueprint. Production pipelines also need access controls, approvals, backups, policy checks and a tested rollback plan.
