01 · Understand the topic

What is Linux & Command Line?

Linux is an operating system used by most cloud servers, containers and many network appliances. DevOps engineers use its command line to inspect systems, configure services, manage files, troubleshoot issues and automate routine work.

Why is it useful in DevOps?

Most production workloads run on Linux. Being comfortable in a terminal helps you investigate incidents quickly, understand how applications run and operate cloud virtual machines without relying on a desktop interface.

02 · Core knowledge

Important concepts to understand

Kernel

The core of the operating system. It manages CPU, memory, devices and processes.

Shell

A command interpreter such as Bash. It reads your commands and starts programs.

Filesystem

A tree of directories starting at /, with standard locations such as /etc, /var and /home.

Users & permissions

Linux controls who can read, write or execute files using ownership and permission bits.

Processes & services

A process is a running program. A service is commonly managed in the background by systemd.

Package manager

Tools such as apt install, update and remove software packages.

04 · Learn in sequence

Step-by-step learning plan

  1. Install Ubuntu in a virtual machine, WSL or another safe lab environment. Learn how to open a terminal and use the shell.
  2. Practise navigation and file operations: pwd, ls, cd, mkdir, touch, cp, mv, rm and cat. Use a temporary lab directory.
  3. Read /etc/passwd, /etc/hosts and files under /var/log. Do not edit system files until you understand their purpose.
  4. Create a user, inspect groups with id, and practise chmod and chown on files inside your lab directory.
  5. Install nginx with apt, inspect it with systemctl, view its process and read its logs. Stop and start it deliberately.
  6. Use df, du, free, top and journalctl to inspect resource usage and service logs. Explain what each output tells you.
05 · Hands-on practice

Mini project / lab

Install nginx on Ubuntu, confirm it is active, find its process, inspect its logs, change the default page and verify it with curl localhost. Write down each command and what it proved.

Tip: Save your notes, commands, screenshots and troubleshooting findings in a GitHub repository. Your learning record becomes part of your portfolio.
