01 · Understand the topic

What is Terraform & Infrastructure as Code?

Infrastructure as Code (IaC) describes infrastructure in files so it can be reviewed, versioned, tested and recreated. Terraform compares your desired configuration with tracked state and proposes the changes needed.

Why is it useful in DevOps?

Manual infrastructure creation is difficult to repeat and audit. IaC makes environments consistent, supports code review and reduces configuration drift when used with a careful workflow.

02 · Core knowledge

Important concepts to understand

Provider

A plugin that lets Terraform manage a platform such as AWS or Azure.

Resource

An infrastructure object Terraform creates or manages.

Variable & output

Inputs make modules reusable; outputs expose useful values.

State

A mapping between Terraform configuration and real objects. Protect it like sensitive operational data.

Plan & apply

Plan previews proposed changes; apply executes the approved plan.

Module

A reusable package of Terraform configuration.

Backend & locking

A backend stores state; supported backends can coordinate locking for team use.

03 · Command reference

Commands and real-world use cases

Run these in a lab environment first. Some commands require the related tool to be installed and configured.

CommandWhat it doesWhen you use it
terraform initInitialise the working directoryDownload providers and configure the backend.
terraform fmt -recursiveFormat configurationKeep HCL consistently formatted.
terraform validateValidate configuration syntax and internal consistencyCatch common configuration errors before planning.
terraform planPreview infrastructure changesReview additions, updates and deletions before execution.
terraform applyApply planned changesCreate or update resources after review.
terraform outputShow output valuesRetrieve values exposed by the configuration.
terraform state listList objects in stateInspect what Terraform currently tracks.
terraform destroyDestroy managed resourcesClean up a disposable lab after confirming the target.
04 · Learn in sequence

Step-by-step learning plan

  1. Install Terraform and learn HCL syntax: blocks, arguments, expressions, variables and outputs.
  2. Configure one provider and create a small resource in a sandbox. Understand authentication and provider versions.
  3. Run init, fmt, validate and plan. Read the plan carefully and understand why each resource changes.
  4. Apply the configuration, inspect outputs and state, then change one value and compare the next plan.
  5. Move repeated configuration into a module. Learn input validation, outputs and module versioning.
  6. Learn remote state, encryption, access control and locking before team usage. Never commit state files or secrets to Git.
05 · Hands-on practice

Mini project / lab

Create a small network and compute resource with Terraform. Use variables and outputs, run fmt/validate/plan, review the plan, apply it, inspect state and destroy the test resources.

Tip: Save your notes, commands, screenshots and troubleshooting findings in a GitHub repository. Your learning record becomes part of your portfolio.
