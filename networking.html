01 · Understand the topic

What is Networking Fundamentals?

Networking is the set of rules and technologies that let computers exchange data. For DevOps, it explains how users reach applications, how services talk to each other and why a connection may fail.

Why is it useful in DevOps?

A large share of infrastructure issues are networking issues: DNS points to the wrong address, a port is blocked, a route is missing, or an application is not listening. Learn the path before learning cloud networking.

02 · Core knowledge

Important concepts to understand

IP address

A logical address used to identify a device on a network. IPv4 addresses look like 192.0.2.10.

Subnet & CIDR

A range of addresses, written for example as 10.0.1.0/24.

DNS

Translates a name such as example.com into an IP address.

Ports

A port identifies the application endpoint on a host; HTTPS commonly uses TCP 443.

TCP & UDP

TCP provides a reliable connection; UDP is connectionless and is used where low overhead matters.

HTTP & TLS

HTTP is the web request/response protocol. HTTPS protects it using TLS encryption.

Routing & firewall

Routing chooses the next hop. Firewalls allow or deny traffic based on rules.

04 · Learn in sequence

Step-by-step learning plan

  1. Understand client, server, router, switch, private/public IP, subnet mask and default gateway. Draw a small home-network diagram.
  2. Learn DNS resolution: domain, resolver, A/AAAA records, CNAME and TTL. Compare a hostname lookup with direct IP access.
  3. Understand TCP handshake, ports and the difference between a service listening locally and a firewall allowing remote access.
  4. Learn HTTP methods, status codes, headers and TLS certificates. Use browser developer tools or curl to inspect responses.
  5. Practise a troubleshooting sequence: resolve DNS, test IP reachability, inspect route, test port, then inspect the application.
  6. Learn CIDR notation and calculate a few small subnets before moving to VPC/VNet design.
05 · Hands-on practice

Mini project / lab

Run a local web server. Confirm the listening port with ss, request it using curl, then stop the service and repeat. Use dig and nc against a test endpoint and record the difference between DNS, routing and port failures.

Tip: Save your notes, commands, screenshots and troubleshooting findings in a GitHub repository. Your learning record becomes part of your portfolio.
